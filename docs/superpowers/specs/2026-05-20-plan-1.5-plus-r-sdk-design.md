# Plan 1.5 + Plan 2 — Extractor Gap Closures + R-SDK Wedge (TypeScript)

**Date:** 2026-05-20
**Status:** Draft — pending spec-reviewer + user approval
**Supersedes for SDK scope:** `docs/superpowers/specs/2026-05-19-agent-ready-renderers-design.md` §4.3 (still authoritative for R-OAS, O-SHAPE, R-MCP; this spec is the focused decomposition for the SDK renderer plus the pre-requisite extractor fixes).
**Substrate baseline:** `substrate/frozen@d402c6a` (Plan 1 final commit). Plan 1.5 will re-cut this tag after completion.

---

## 1. Context

Plan 1 froze the agent-ready substrate (R-OAS + O-SHAPE) at `substrate/frozen@d402c6a`. The final integration review surfaced two upstream extractor gaps documented in `KNOWN_GAPS.md`:

1. **GraphQL auth-orphan** — `src/extractors/graphql.ts` emits a default bearer `auth_scheme` node but no `auth_requires` edges, so GraphQL-sourced operations project with `components.securitySchemes == {}`.
2. **OpenAPI `requestBody` not projected** — `src/extractors/openapi3-ops.ts` records request bodies as op-level `request_content` claims rather than as `parameter` nodes with `location: "body"`, so the synthetic OpenAPI emits no `requestBody` on POST/PUT/PATCH.

Both gaps materially affect Plan 2 (R-SDK) — without them, the wedge SDK would either omit POST/PUT/PATCH inputs entirely or ship broken auth contracts for GraphQL products. The user-locked sequencing is **Plan 1.5 first** (surgical extractor fixes + golden regen + tag re-cut), then **Plan 2** (R-SDK wedge against the closed-gap substrate).

## 2. Locked Decisions (from brainstorming, 2026-05-20)

These decisions are not open for re-litigation in plan-writing or implementation; they are inputs.

1. **Plan 2 plugin scope** — minimum-viable wedge: `resource-tree` + `errors` + `runtime`. Defer `pagination`, `retries`, `streaming`, `webhooks` to a future Plan 2b. Trade-off acknowledged: the wedge SDK does not auto-paginate, retry, or stream.
2. **Sequencing** — Plan 1.5 (extractor fixes) precedes Plan 2. Re-cut `substrate/frozen` to the post-1.5 commit before Plan 2 starts. Plan 2 builds against the new substrate.
3. **Packaging** — R-SDK emits its npm package as a top-level `skillship build` artifact at `{outDir}/{product}/sdk/`, alongside `openapi.json`, `SKILL.md`, `.mcp.json`, `llms.txt`. A `--skip-sdk` flag protects the build hot path for users who don't want SDK regeneration on every build.
4. **Conformance bar** — `tsc --noEmit` strict on the emitted package is the hard gate. Unit tests on each plugin in isolation. Committed golden-file lock on the emit tree. **No msw runtime conformance in Plan 2** (defers with pagination/retries/streaming plugins; revisits in Plan 2b).

## 4. Plan 1.5 — Extractor Gap Closures

### 4.1 Goal

Two surgical fixes to existing extractors, two regenerated golden files, retag. No renderer changes (R-OAS already handles both projections correctly — verified in Plan 1 Tasks 2 and 3).

### 4.2 Gap 1 Fix — `src/extractors/graphql.ts`

**Current behavior** (`src/extractors/graphql.ts:159`): extractor emits a default `auth_scheme` node (bearer) but returns `edges: []`. No `auth_requires` edge connects operations to the auth scheme.

**Fix:** When emitting the default `auth_scheme` node, also emit one `auth_requires` edge per operation node into that auth_scheme. Edge shape mirrors the REST extractor (`src/extractors/openapi3-ops.ts`): `{ kind: 'auth_requires', from: opId, to: authSchemeId, source_id: <sourceId>, rationale: null }`. R-OAS already projects `auth_requires` correctly into `securitySchemes` + per-op `security` (verified Plan 1 Task 3).

**Acceptance:** After the fix, `tests/fixtures/golden/oas-graphql-minimal.json` will contain a non-empty `components.securitySchemes` (one bearer entry) and each GraphQL operation will have a `security: [...]` array.

### 4.3 Gap 2 Fix — `src/extractors/openapi3-ops.ts`

**Current behavior:** `requestBody` is stored as an op-level `request_content` claim. R-OAS's `buildParams` only constructs `requestBody` from parameter rows with `location: "body"`, so the existing claim is never consumed.

**Fix:** When an operation has a `requestBody`, emit a child `parameter` node alongside the existing query/header/path parameter nodes, with:
- `kind: 'parameter'`
- claim `location: 'body'` (string-valued)
- claim `required: true|false` (from `requestBody.required`, default false per OpenAPI spec)
- claim `name: 'body'` (fixed placeholder — the renderer ignores `name` for body params)
- claim `schema_ref: <raw $ref string>` when the body's `application/json` schema has a `$ref` (R-OAS strips the prefix; see `src/renderers/oas.ts` `buildResponses`)
- claim `content_type: 'application/json'` (Plan 1.5 supports only JSON bodies; multipart/form-encoded deferred)

The op-level `request_content` claim can remain (it's currently dead weight, but removing it is out of scope to keep the diff minimal).

**Acceptance:** After the fix, `tests/fixtures/golden/oas-minimal.json`'s `createProject` POST will contain a `requestBody` block with `application/json` content referencing `#/components/schemas/ProjectInput`.

### 4.4 Test Posture

**Unit tests** (TDD, RED → GREEN → REFACTOR):
- `tests/extractors/graphql-auth.test.ts` — assert `extractGraphql` returns at least one `auth_requires` edge from each operation to the bearer auth_scheme.
- `tests/extractors/openapi3-ops-requestbody.test.ts` — assert `extractOpenapi3Ops` emits a body parameter node with the expected claims for an op with a `requestBody`.

**Golden regen:** Use the existing `tests/renderers/oas-golden-helpers.ts` flow (the byte-identical-code-path guarantee from Plan 1 Task 7). Both goldens will change; the existing `oas-golden.test.ts` byte-identity lock test must pass after regen.

**Substrate retag:** Delete the old `substrate/frozen` tag and re-create it at the Plan 1.5 final commit. `KNOWN_GAPS.md` updated — both gaps marked **resolved** with the resolving commit SHA, kept in the doc as historical record (not deleted).

### 4.5 Files Touched (Plan 1.5)

- Modify: `src/extractors/graphql.ts`, `src/extractors/openapi3-ops.ts`
- Modify: `tests/fixtures/golden/oas-minimal.json`, `tests/fixtures/golden/oas-graphql-minimal.json` (regenerated)
- Modify: `KNOWN_GAPS.md` (mark both gaps resolved)
- Create: `tests/extractors/graphql-auth.test.ts`, `tests/extractors/openapi3-ops-requestbody.test.ts`

Estimated size: <250 LOC total. No renderer touches. No new dependencies.

### 4.6 Risks (Plan 1.5)

- **R1.5-1 — Cascading test failures.** Other tests may have implicitly relied on the gap behavior (e.g., asserting `components.securitySchemes == {}` for GraphQL or absence of `requestBody`). Mitigation: full preflight after each extractor fix; any failing test that was asserting the broken behavior is updated to assert the correct behavior in the same commit.
- **R1.5-2 — Edge claim shape mismatch.** R-OAS reads `auth_requires` edges via a specific query pattern; if the new GraphQL edge's columns don't match, projection silently fails. Mitigation: the extractor-fix tests assert the edge appears in `components.securitySchemes` post-render, not just in the graph (end-to-end coverage).

## 5. Plan 2 — R-SDK Wedge (TypeScript)

### 5.1 Goal

Plan 2 produces a publishable, idiomatic TypeScript SDK npm package from the synthetic OpenAPI document, using a 3-plugin wedge on top of `@hey-api/openapi-ts`. The emitted package passes `tsc --noEmit` strict and demonstrates nested resource calls (`client.projects.create(input)`), typed errors, and a fetch-based runtime with auth injection.

### 5.2 Architecture

```
graph (sqlite, post-Plan-1.5 substrate)
   └─▶ R-OAS (Plan 1) ─▶ synthetic OpenAPI 3.1 string (in-memory)
                                  │
                                  ▼
                  ┌─────────────────────────────────────┐
                  │  src/renderers/sdk.ts                │
                  │  renderSdkPackage(input): Result     │
                  │                                      │
                  │  invokes @hey-api/openapi-ts         │
                  │  with base plugins:                  │
                  │    @hey-api/typescript               │
                  │    @hey-api/sdk                      │
                  │  and skillship plugins:              │
                  │    resource-tree                     │
                  │    errors                            │
                  │    runtime                           │
                  └─────────────────────────────────────┘
                                  │
                       emit to temp dir, run tsc
                                  │
                       ┌──────────┴──────────┐
                       │ tsc exit code 0?    │
                       └──────────┬──────────┘
                           yes    │    no
                                  ▼    ▼
                     atomic-move    surface tsc diagnostics
                     to {outDir}/   exit non-zero
                     {product}/     leave nothing at outDir
                     sdk/
```

### 5.3 Components

**`src/renderers/sdk.ts`** (orchestrator)
- Exported: `renderSdkPackage(input: RenderSdkInput): Promise<SdkRenderResult>`.
- `RenderSdkInput`: `{ oasJson: string; productName: string; outDir: string; overlay: CodegenOverlay; license?: string; }`.
- **`outDir` semantics:** `outDir` is the **fully-resolved final destination** for the emitted SDK tree (i.e., the caller passes `join(skillDir, "sdk")` directly; the renderer does NOT append `/sdk/` or the product slug internally). The renderer's atomic-move target is exactly `input.outDir`. `SdkRenderResult.outDir` echoes that same path.
- `SdkRenderResult`: `{ outDir: string; files: readonly string[]; typecheckExitCode: number; }`.
- Responsibilities (in order): (1) write `oasJson` to a temp file; (2) invoke `@hey-api/openapi-ts` programmatically with the 3-plugin wedge; (3) write `package.json` / `tsconfig.json` / `README.md` / `LICENSE` / `.npmignore` templates from O-SHAPE config; (4) Prettier-format emitted TS; (5) run `tsc --noEmit` against the emit dir, capture exit code; (6) on exit 0, atomic-move temp → `input.outDir`.

**`src/sdk-plugins/resource-tree.ts`** (Hey API custom plugin)
- **Data source:** the plugin reads `resources` rename/namespace rules from the `overlay: CodegenOverlay` object passed through the plugin factory closure. The `x-skillship-codegen` vendor extension stamped into `oasJson` by `applyOverlayToDoc` is treated as informational (preserved for downstream consumers of the OpenAPI doc) and is NOT re-parsed by the plugin. There is a single source of truth — the `CodegenOverlay` Zod-validated object.
- Reshapes the generated client into nested namespaces: `client.projects.list()`, `client.projects.create(input)`, `client.users.list()`.
- Declares Hey API plugin dependencies: `@hey-api/typescript`, `@hey-api/sdk`.
- Default namespacing when no overlay rule matches: use the operation's `tags[0]` (R-OAS derives this from the REST path's first non-template segment or GraphQL root type, per spec §4.1 amendment).

**`src/sdk-plugins/errors.ts`** (Hey API custom plugin)
- Emits a typed error hierarchy file with exactly these classes:
  - `APIError` (base) — props: `status: number`, `requestId: string | null`, `body: unknown`, `code: string | null`.
  - `BadRequestError extends APIError` (400)
  - `UnauthorizedError extends APIError` (401)
  - `ForbiddenError extends APIError` (403)
  - `NotFoundError extends APIError` (404)
  - `RateLimitError extends APIError` (429)
  - `InternalServerError extends APIError` (5xx — any status 500-599)
- Wraps the SDK transport's response handling so non-2xx responses throw the corresponding class. Falls back to `APIError` for status codes not in the explicit set.

**`src/sdk-plugins/runtime.ts`** (Hey API custom plugin)
- Emits the `Client` constructor and the fetch wrapper:
  - Constructor takes `{ baseUrl: string, auth: AuthConfig, defaultHeaders?: Record<string,string>, fetch?: typeof fetch, timeout?: number }`.
  - `AuthConfig` is a discriminated union driven by R-OAS's projected `securitySchemes`: `{ kind: 'bearer', token: string }`, `{ kind: 'apiKey', value: string, in: 'header'|'query', name: string }`, `{ kind: 'basic', username: string, password: string }`.
  - Injects auth into every request per the projected schemes; if multiple schemes are projected for an op, applies all (matches OpenAPI semantics where multiple `security` entries are AND).
  - Exposes `onRequest` / `onResponse` interceptor hooks for advanced users.
- No retries / no backoff / no idempotency-key generation in Plan 2 (deferred with the `retries` plugin).

**`src/cli/build.ts`** (wiring change)
- Add `import { renderSdkPackage } from "../renderers/sdk.js";`.
- Add `readonly skipSdk?: boolean;` to `RunBuildOptions`.
- After the existing `writeAll` artifact list, if `!opts.skipSdk`, invoke `renderSdkPackage` and append its emitted files to `BuildResult.artifacts`.
- On `renderSdkPackage` failure (typecheck non-zero), surface the error and exit non-zero — do NOT silently drop the SDK.

### 5.4 Data Flow (concrete)

1. `runBuild(opts)` parses config, ingests sources, builds the graph.
2. R-OAS renders the synthetic OpenAPI string (in-memory).
3. Existing top-level artifacts (SKILL.md, openapi.json, .mcp.json, llms.txt, llms-full.txt, manifest.json) are written.
4. If `--skip-sdk` is not set, `renderSdkPackage({ oasJson, productName, outDir: join(skillDir, "sdk"), overlay })` is invoked.
5. R-SDK writes `oasJson` to a temp file, runs `@hey-api/openapi-ts` with the 3 wedge plugins, Prettier-formats output, runs `tsc --noEmit`.
6. On `tsc` exit 0, atomic-move temp dir to the caller-resolved `input.outDir` (which the build wiring set to `join(skillDir, "sdk")`, i.e., `{cli-outDir}/{product}/sdk/` from the user's POV). On failure, leave that path untouched and surface diagnostics.

### 5.5 Success Criteria

Plan 2 is done when ALL hold:

1. `skillship build` on a fixture in-dir emits `{outDir}/{product}/sdk/` as a publishable npm package (has `package.json` with valid ESM exports, `tsconfig.json` with `strict: true`, generated `src/` with no `any` in the public API, `README.md`, `LICENSE`, `.npmignore`).
2. The emitted SDK passes `tsc --noEmit` strict against its own `tsconfig.json`.
3. The emitted SDK shape demonstrates nested resources: `client.projects.create({...})` and `client.projects.list()` typecheck against the generated types (test imports them and asserts).
4. The emitted SDK's error hierarchy contains exactly the 7 declared classes (`APIError` + 6 subclasses); non-2xx response handling routes through them.
5. Two committed golden trees (`tests/fixtures/golden/sdk-minimal/` from `tests/fixtures/openapi3/minimal.yaml`; `tests/fixtures/golden/sdk-graphql-minimal/` from `tests/fixtures/graphql/minimal.graphql`) and a byte-identity lock test pass.
6. Plugin unit tests for `resource-tree`, `errors`, `runtime` all pass.
7. Determinism: two consecutive `renderSdkPackage` calls produce byte-identical emit trees.
8. `--skip-sdk` flag short-circuits SDK generation without affecting other artifacts.

### 5.6 Error Handling

Five failure categories, all non-zero exit with actionable messages:

1. **R-OAS upstream error** — handled by Plan 1; no Plan 2 change.
2. **Hey API engine error** — surface verbatim (Hey API errors are typically structured; pass through `error.message`).
3. **Plugin error** (skillship plugin throws) — wrap with `[plugin:${pluginName}] ${error.message}`, preserve original stack.
4. **Typecheck failure** — the hard gate. Capture `tsc` exit code via `tsc --noEmit; echo "TSC_EXIT=$?"` pattern. Print all diagnostics. Exit non-zero. Do NOT atomic-move.
5. **Emit-dir error** — filesystem failures during temp-write or atomic-move. Surface OS error verbatim.

Atomic guarantee: no half-written package at `{outDir}/{product}/sdk/`. The renderer writes to a `mkdtempSync`-allocated temp dir; only on full success (steps 1–5 all green) does `renameSync` move it to the final location. Any failure leaves the final outDir untouched.

### 5.7 Testing (TDD)

**Plugin unit tests (TDD, RED → GREEN per task):**
- `tests/sdk-plugins/resource-tree.test.ts` — given a Hey API IR snapshot of operations plus a `CodegenOverlay` object with `resources` rules, assert the plugin produces the expected nested namespace structure. Tests must also cover the fallback path (no overlay rule matches → use `tags[0]`).
- `tests/sdk-plugins/errors.test.ts` — assert the generated error file declares exactly the 7 classes with correct status-code mapping in the dispatch function.
- `tests/sdk-plugins/runtime.test.ts` — assert the generated `Client` class has the expected constructor signature and that auth-injection logic emits correctly for each `securityScheme` kind (bearer, apiKey-header, apiKey-query, basic).

**Golden lock test:** `tests/renderers/sdk-golden.test.ts` mirrors `oas-golden.test.ts` pattern — uses a shared `sdk-golden-helpers.ts` module to render both fixtures' SDKs and asserts byte-identity against committed `tests/fixtures/golden/sdk-{minimal,graphql-minimal}/` trees. The lock test also runs `tsc --noEmit` against each golden's `tsconfig.json` as part of the same suite.

**Determinism test:** in `tests/renderers/sdk.test.ts`, render the SDK twice in one process, compare emit trees byte-by-byte.

**Build wiring test:** `tests/cli/build-sdk.test.ts` exercises `runBuild` end-to-end (post-Plan-1.5 substrate), asserts `{outDir}/{product}/sdk/package.json` exists and parses. Also asserts `--skip-sdk` short-circuits.

### 5.9 Risks (Plan 2)

- **R2-1 — Hey API plugin API drift.** Stainless's own scar tissue is engine-coupling. Mitigation: pin exact `@hey-api/openapi-ts` version in `package.json`; vendor the relevant plugin type contracts (or at least re-export them with a version comment); CI canary job runs the SDK golden test against `@hey-api/openapi-ts@latest` weekly and alerts on break. This is the #1 technical risk.
- **R2-2 — Quality ceiling bounded by Hey API's emitter.** If a specific module of the wedge SDK cannot reach idiomatic via our plugins, escalate to a hand-written emitter for *that module only* (not the whole engine). Operational trigger: one focused implementation session of plugin-tuning fails to produce a green golden + tsc-pass for that module → switch to hand-written for that module. Bounded scope by construction.
- **R2-3 — Build hot-path cost.** SDK generation adds seconds (potentially tens) to `skillship build`. Mitigation: `--skip-sdk` flag (locked decision); future Plan 2c could add incremental render-on-graph-delta.
- **R2-4 — Golden churn.** The SDK golden trees are large (potentially hundreds of files); any plugin tweak rewrites the golden. Mitigation: review golden diffs by category (only `src/` files matter for behavior; `package.json` / `tsconfig.json` / `README.md` changes are reviewed separately). Document the review process in `tests/fixtures/golden/sdk-minimal/README.md`.

### 5.10 Scope (Plan 2)

**In:** `src/renderers/sdk.ts`, three plugin files under `src/sdk-plugins/`, `src/cli/build.ts` wiring + `--skip-sdk` flag, two SDK golden trees + lock test + tsc-gate test, three plugin unit-test files, `tests/cli/build-sdk.test.ts`, `tests/renderers/sdk.test.ts` (determinism), README/LICENSE/.npmignore templates in `src/renderers/sdk-templates/`, `tests/fixtures/golden/sdk-minimal/README.md` documenting the golden-diff review process (per R2-4 mitigation).

**Out:** `pagination`, `retries`, `streaming`, `webhooks` Hey API plugins. msw-based runtime conformance suite. Python SDK. R-MCP wiring (Plan 3 — separate spec). Hand-written-emitter fallback (only invoked under R2-2 operational trigger; not pre-built). Incremental render-on-graph-delta optimization. GitHub-release-automation. Hosted control plane.

### 5.11 Open Decisions (do not block planning)

- **Plugin file layout** — `src/sdk-plugins/<name>.ts` flat vs. `src/sdk-plugins/<name>/index.ts` per-plugin-dir. Default flat for the 3 wedge plugins; revisit when plugin count grows in Plan 2b.
- **`package.json` template field set** — minimum viable: `name`, `version`, `type: "module"`, `main`, `types`, `exports`, `license`, `repository`. Other fields (`keywords`, `author`, `bugs`) deferred.
- **Pin strategy for `@hey-api/openapi-ts`** — exact pin (`x.y.z`) recommended; caret-pin (`^x.y.z`) is a riskier choice given R2-1. Locked at exact pin in plan-writing.
